# 히스테리시스 임계값 (Hysteresis Threshold)

2026-06-05 · 가로 연표 sticky 핀 버그를 고치며 배운 것

## 한 줄 정의

상태를 켜는 임계값과 끄는 임계값을 다르게 두는 기법입니다. 두 값 사이의 구간이 완충지대가 되어, 경계 근처에서 상태가 빠르게 켜졌다 꺼졌다 하는 진동(oscillation)을 막습니다.

## 겪은 문제

가로 연표 밴드에 "스크롤하면 핀 고정 + 헤더 숨김" 동작을 넣었는데, 페이지 맨 위에서 스크롤하면 화면 전체가 뒤흔들렸습니다.

원인은 단일 임계값이었습니다.

- 핀 조건: `scrollY > 0` (사실상 1px만 내려가도 발동)
- 핀 되는 순간: 헤더가 −57px 슬라이드아웃 + 밴드가 그 자리로 이동 → 화면이 57px 출렁
- 사용자가 1~2px 위로 올리면: 핀 해제 → 헤더 복귀 → 또 출렁
- 경계(scrollY ≈ 0) 근처에서 스크롤할 때마다 켜짐/꺼짐이 반복 → "페이지가 뒤흔들린다"

상태 전환 자체가 화면을 움직이는데, 전환 기준점이 하나뿐이면 그 지점 근처에서 무한히 왕복할 수 있습니다.

## 해결

켜는 값과 끄는 값을 분리했습니다.

```tsx
useEffect(() => {
  const onScroll = () => {
    const y = window.scrollY
    setPinned((prev) => (prev ? y > 40 : y > 140))
  }
  onScroll()
  window.addEventListener('scroll', onScroll, { passive: true })
  return () => window.removeEventListener('scroll', onScroll)
}, [])
```

- 핀 켜기: 내려가다 **140px 초과** 시
- 핀 끄기: 올라오다 **40px 미만** 시
- 40~140px 구간: 직전 상태 유지 (완충지대 100px)

핀이 켜진 직후 화면이 57px 출렁여도, 스크롤 위치가 완충지대 안에 있으면 상태가 바뀌지 않으므로 왕복 진동이 구조적으로 불가능합니다.

핵심은 `setPinned((prev) => ...)` 형태입니다. 현재 상태(prev)에 따라 적용할 임계값이 달라지므로, 상태가 조건의 일부가 됩니다. 이것이 히스테리시스의 정의 그 자체입니다: **출력이 현재 입력만이 아니라 이력(history)에 의존한다.**

## 일상 속 같은 원리

- 보일러 온도조절기: 22도 설정 시 21.5도에서 켜고 22.5도에서 끕니다. 22.0도 하나로 제어하면 보일러가 초 단위로 켜졌다 꺼졌다 합니다.
- 노트북 배터리 경고: 20%에서 경고를 띄우고, 21%로 충전됐다고 바로 지우지 않습니다.
- 자동차 냉각팬, 에어컨 컴프레서, 슈미트 트리거(전자회로) 전부 같은 구조입니다.

## 프론트엔드에서 쓰는 곳

- sticky/fixed 전환처럼 **전환 자체가 레이아웃을 움직이는** 모든 스크롤 트리거
- 스크롤 방향 감지로 헤더 숨기기/보이기 (내릴 때 숨기고 올릴 때 보일 때, 방향 전환 지점 떨림 방지)
- IntersectionObserver로 같은 효과를 내려면 threshold 두 개짜리 옵저버 둘을 쓰거나 rootMargin을 비대칭으로 줘야 해서, 단순 스크롤 리스너 + 이중 임계가 더 읽기 쉬울 때가 많습니다

## 판별법

"상태가 바뀌는 순간 화면(또는 측정값)이 움직이고, 그 움직임이 다시 상태 조건에 영향을 주는가?" — 그렇다면 단일 임계값은 진동의 씨앗입니다. 켜는 값과 끄는 값을 벌려 두세요. 완충 폭은 전환이 일으키는 변위보다 크게 잡으면 안전합니다 (이번 사례: 전환 변위 57px < 완충 100px).
